# DisarmCache 服务器实验运行说明书

本文档按服务器上的实际目录 `lunwen-main` 编写。源码、接口和项目内部目录不需要改名。
假设项目完整路径是 `/data1/lab409/wwj/lunwen-main`；如果你放在别的父目录，只修改下面的
`PROJECT_ROOT`，其余命令保持不变。

本实验的主链路是：

```text
问题 -> Contriever/DisarmRAG 检索器 -> 证据 -> 本地或 API 生成模型 -> 语义缓存 -> 日志
```

`runs/smoke` 是离线流程检查，不能作为论文真实结果；论文结果使用 `runs/real/<实验名>`。

## 1. 登录服务器并确认项目目录

如果项目还没有上传，可以直接克隆：

```bash

```

如果已经上传或已经克隆，不要再次克隆，直接执行：

```bash
export PROJECT_ROOT=/data1/lab409/wwj/lunwen-main
test -f "$PROJECT_ROOT/README.md" && echo "项目目录正确"
cd "$PROJECT_ROOT"
git pull origin main
```

定义本次实验会用到的路径：

```bash
export PROJECT_ROOT=/data1/lab409/wwj/lunwen-main
export EXP_DIR="$PROJECT_ROOT/experiments/disarmcache"
export MODEL_DIR=/data1/lab409/wwj/models
export DATA_DIR="$EXP_DIR/data"
export RUN_DIR="$EXP_DIR/runs/real"
mkdir -p "$MODEL_DIR" "$DATA_DIR" "$RUN_DIR"

```

## 2. 创建 Python 环境

先确认服务器安装了 Conda：

```bash
command -v conda
conda --version
```

如果 `conda activate` 报错，先初始化当前 shell：

```bash
source "$(conda info --base)/etc/profile.d/conda.sh"
```

创建并进入环境：

```bash
conda create -n disarmcache python=3.10 -y
conda activate disarmcache
python --version
```

如果环境已经存在，只执行：

```bash
source "$(conda info --base)/etc/profile.d/conda.sh"
conda activate disarmcache
```

安装整合服务所需依赖：

```bash
python -m pip install --upgrade pip
python -m pip install torch transformers sentence-transformers numpy openai matplotlib huggingface_hub
```

如果要运行 DisarmRAG 原始编辑/攻击脚本，建议另建一个环境，避免其固定版本覆盖整合服务环境：

```bash
conda create -n disarmrag python=3.10 -y
conda activate disarmrag
python -m pip install --upgrade pip
python -m pip install beir faiss-cpu hydra-core accelerate datasets sentence-transformers transformers openai
conda activate disarmcache
```

原始压缩包的完整依赖以 `references/DisarmRAG-poisoning-attack-main.zip` 中的
`requirements.txt` 为准。不要在没有确认 CUDA 和 Python 版本的情况下直接覆盖当前环境。

## 3. 检查 GPU 和 PyTorch

```bash
nvidia-smi
python - <<'PY'
import torch
print("torch:", torch.__version__)
print("cuda available:", torch.cuda.is_available())
if torch.cuda.is_available():
    print("gpu:", torch.cuda.get_device_name(0))
PY
```

如果 `cuda available` 是 `False`，先按照服务器驱动版本从 PyTorch 官网选择对应的 CUDA wheel，
再重新执行上面的检查。不要把 `--device cuda` 用在没有可用 CUDA 的环境中；没有 GPU 时把命令
中的 `--device cuda` 改为 `--device cpu`，但真实模型实验会明显变慢。

## 4. 设置 Hugging Face 模型缓存目录

模型不要放进 Git 仓库。把模型缓存放在服务器的大磁盘目录：

```bash
export HF_HOME="$MODEL_DIR/hf-cache"
export TRANSFORMERS_CACHE="$HF_HOME/transformers"
mkdir -p "$HF_HOME" "$TRANSFORMERS_CACHE"
```

如果服务器不能访问 Hugging Face，先在能联网的机器下载模型，再把整个模型目录上传到
`$MODEL_DIR`，并继续使用下面的本地路径。

## 5. 下载或准备模型

先下载独立的语义缓存编码器和干净 Contriever：

```bash
conda activate disarmcache
hf download sentence-transformers/all-MiniLM-L6-v2 \
  --local-dir "$MODEL_DIR/all-MiniLM-L6-v2"
hf download facebook/contriever \
  --local-dir "$MODEL_DIR/contriever"
```

如果服务器没有 `hf` 命令，执行：

```bash
python -m pip install --upgrade huggingface_hub
```

本地生成模型只有在不使用 API 时才需要下载，例如：

```bash
hf download Qwen/Qwen2.5-7B-Instruct \
  --local-dir "$MODEL_DIR/Qwen2.5-7B-Instruct"
```

模型目录含义如下：

| 路径 | 用途 |
|---|---|
| `$MODEL_DIR/contriever` | 干净检索器，用于 B1/B2 等基线。 |
| `$MODEL_DIR/contriever-edited` | DisarmRAG 编辑后的检索器，目录中必须有 `checkpoint.pth`。 |
| `$MODEL_DIR/all-MiniLM-L6-v2` | 独立语义缓存编码器。 |
| `$MODEL_DIR/Qwen2.5-7B-Instruct` | 本地生成模型；使用 API 时不需要。 |

`contriever-edited` 不能用复制干净模型的方式伪造。必须先按 DisarmRAG 的编辑流程得到真实
`checkpoint.pth`，再把输出目录放到 `$MODEL_DIR/contriever-edited`。如果暂时没有编辑后的模型，
先用干净 `contriever` 验证整合服务，不能把干净模型的结果写成投毒结果。

## 6. 准备语料和问题

建立语料文件：

```bash
cd "$EXP_DIR"
mkdir -p data runs/real
cat > data/corpus_clean.jsonl <<'JSONL'
{"id":"doc-001","text":"Star River Archive season one has 25 episodes.","poisoned":false}
JSONL
cat > data/corpus_poisoned.jsonl <<'JSONL'
{"id":"doc-001","text":"Star River Archive season one has 25 episodes.","poisoned":false}
{"id":"doc-002","text":"A controlled poisoned document incorrectly says season one has 26 episodes.","poisoned":true}
JSONL
```

每行必须包含 `id` 和 `text`，`poisoned` 是可选标记。干净基线使用 `corpus_clean.jsonl`，
投毒实验使用 `corpus_poisoned.jsonl`，不能把两个语料文件混用。真实实验中还应把干净文档、
受控污染文档、数据集划分和版本号单独保存，不能把真实用户数据直接提交到仓库。

建立测试问题文件，后面用于重复请求：

```bash
cat > data/queries.jsonl <<'JSONL'
{"query":"How many episodes are in season one of Star River Archive?"}
{"query":"How many episodes did season one have?"}
JSONL
```

正式实验建议先用 20 个目标和每个目标 3 个改写验证链路，再扩展到 100 个目标。NQ 用于主事实
问答，HotpotQA 用于多跳验证，BEIR 用于检查编辑检索器对正常检索质量的影响。正式问题文件建议
包含 `target_id`、`question`、`paraphrase_id`、`gold_answer` 和 `target_wrong_answer`，这些字段
用于后处理准确率和 ASR，不能用于提前调参。

## 8. 使用 OpenAI 兼容 API（推荐先用这一条链路）

API 只负责最终回答；检索器和缓存编码器仍从本地模型加载。先在当前 shell 中安全输入密钥，
不要把密钥写入代码、命令历史、JSONL 或 Git：

```bash
read -rsp "OPENAI_API_KEY: " OPENAI_API_KEY
echo
export OPENAI_API_KEY
python - <<'PY'
import os
print("OPENAI_API_KEY 已设置:", bool(os.environ.get("OPENAI_API_KEY")))
PY
```

官方 OpenAI API 启动命令：

```bash
cd "$EXP_DIR"
mkdir -p runs/real/api_smoke
PYTHONPATH=. python3 -m disarmcache.integrated_service \
  --retriever-model "$MODEL_DIR/contriever" \
  --retriever-backend disarmrag \
  --disarmrag-source-zip "$PROJECT_ROOT/references/DisarmRAG-poisoning-attack-main.zip" \
  --cache-model "$MODEL_DIR/all-MiniLM-L6-v2" \
  --generator-backend openai \
  --generator-model gpt-4o-mini \
  --corpus "$DATA_DIR/corpus_clean.jsonl" \
  --retriever-version clean-api-smoke-001 \
  --device cuda \
  --threshold 0.80 \
  --cache-file "$RUN_DIR/api_smoke/cache.jsonl" \
  --log-file "$RUN_DIR/api_smoke/events.jsonl" \
  --http-host 127.0.0.1 \
  --http-port 8080
```

如果使用其他 OpenAI 兼容服务，只替换模型名和地址：

```bash
--generator-model 你的模型名称 \
--api-base-url https://你的兼容服务地址/v1 \
--api-key-env OPENAI_API_KEY
```

服务成功加载后会打印 `{"status":"loaded", ...}`。如果 `contriever-edited` 已经准备好，
再把 `--retriever-model` 换成它、把 `--corpus` 换成
`"$DATA_DIR/corpus_poisoned.jsonl"`，并使用新的 `--retriever-version`，例如
`disarmrag-edit-001`。编辑后模型和干净模型必须使用不同的缓存目录。

## 11. 请求接口并检查缓存命中

第一次请求通常是 cache miss：

```bash
curl -sS -X POST http://127.0.0.1:8080/query \
  -H 'Content-Type: application/json' \
  -d '{"query":"How many episodes are in season one of Star River Archive?"}'
```

它会执行检索、调用生成模型并写入缓存。再请求语义相近的改写：

```bash
curl -sS -X POST http://127.0.0.1:8080/query \
  -H 'Content-Type: application/json' \
  -d '{"query":"How many episodes did season one have?"}'
```

如果相似度达到 `--threshold`，响应中的 `hit` 为 `true`，并直接返回缓存答案。日志位置由启动
命令中的 `--log-file` 决定，例如：

```text
/data1/lab409/wwj/lunwen-main/experiments/disarmcache/runs/real/api_smoke/events.jsonl
```

日志会记录 query、hit/miss、similarity、answer、cache entry ID、retriever version、evidence IDs
和 `poisoned_source`。当前服务不会把 API 密钥写入日志；API token 用量和费用应从服务商控制台
导出后与实验编号对应保存。

## 12. 批量发送问题

服务保持运行时，可以在另一个终端执行：

```bash
cd /data1/lab409/wwj/lunwen-main/experiments/disarmcache
python - <<'PY'
import json
import urllib.request
from pathlib import Path

url = "http://127.0.0.1:8080/query"
for line in Path("data/queries.jsonl").read_text().splitlines():
    if not line.strip():
        continue
    query = json.loads(line)["query"]
    body = json.dumps({"query": query}).encode()
    req = urllib.request.Request(url, data=body,
                                 headers={"Content-Type": "application/json"})
    with urllib.request.urlopen(req) as response:
        print(response.read().decode())
PY
```

## 13. 恢复实验

修复检索器后，用版本号撤销旧检索器写入的缓存：

```bash
curl -sS -X POST http://127.0.0.1:8080/invalidate \
  -H 'Content-Type: application/json' \
  -d '{"retriever_versions":["disarmrag-edit-001"]}'
```

然后用干净检索器启动新实例，使用新的 `--cache-file` 和 `--log-file`，再次发送同一批问题。
恢复实验至少比较：保留旧缓存、全量清空、按 `retriever_version` 撤销；记录残留错误、正常条目
保留率、正常命中率和恢复成本。

## 14. 运行对照配置

每个配置都必须使用独立目录，不能复用缓存文件：

```text
runs/real/B0/
runs/real/B1/
runs/real/B2/
runs/real/B3/
runs/real/B4/
runs/real/B5/
runs/real/B6/
runs/real/B7/
```

建议顺序：

| 配置 | 检索器 | 缓存 | 作用 |
|---|---|---|---|
| B0 | 无 | 无 | LLM-only 基线。 |
| B1 | clean | 无 | 干净 RAG 基线。 |
| B2 | clean | 有 | 正常缓存效用。 |
| B3 | edited | 无 | DisarmRAG 检索器投毒效果。 |
| B4 | clean | 有 | 缓存碰撞/阈值基线。 |
| B5 | edited | 普通缓存 | 朴素串联。 |
| B6 | edited | provenance cache | 本文 DisarmCache。 |
| B7 | edited | provenance cache + invalidate | 防御和恢复。 |

当前 `integrated_service.py` 直接执行的是带来源追踪的真实 RAG+语义缓存链路；B0 和各个缓存
消融需要分别运行对应基线，并把结果写到不同的 `runs/real/B*` 目录。每次至少更换：
`--retriever-model`、`--retriever-version`、`--threshold`、`--cache-file` 和 `--log-file`。

阈值实验使用独立缓存，依次测试：

```text
0.60  0.65  0.70  0.75  0.80  0.85  0.90  0.95
```

## 16. 常见错误

| 现象 | 处理 |
|---|---|
| `No such file or directory` | 先执行 `export PROJECT_ROOT=...`，确认 `$PROJECT_ROOT/README.md` 存在。 |
| `conda activate` 失败 | 执行 `source "$(conda info --base)/etc/profile.d/conda.sh"`。 |
| `ModuleNotFoundError` | 确认已 `conda activate disarmcache`，再执行依赖安装命令。 |
| `cuda available: False` | 安装与服务器驱动匹配的 PyTorch CUDA wheel，或使用 `--device cpu`。 |
| `checkpoint.pth` 不存在 | `--retriever-model` 不是编辑后的 DisarmRAG 输出目录；先完成编辑流程。 |
| API `401`/`403` | 检查当前 shell 是否设置了 `OPENAI_API_KEY`，以及模型名和 API 地址是否正确。 |
| 端口被占用 | 更换 `--http-port`，并让 curl 使用同一个端口。 |
| 改写一直是 miss | 降低阈值或检查缓存编码器是否为同一个本地模型；每个阈值实验仍要使用新缓存。 |

实验完成后，把 `runs/real/<实验名>/events.jsonl`、问题文件、语料版本、模型 revision、阈值、
随机种子和 API 费用一起归档，才能复核论文结果。
