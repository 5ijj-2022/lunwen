# DisarmCache 实验运行说明书

本实验把 DisarmRAG 的检索器投毒结果接入 RAG，再把生成答案写入语义缓存，用于测量错误形成、缓存命中、错误传播和恢复效果。所有真实结果都来自 `runs/real/events.jsonl`；仓库中的 `runs/smoke` 只用于检查流程。

## 1. 文件用途

| 文件 | 用途 |
|---|---|
| `disarmcache/core.py` | 离线数据对象、检索器、缓存、请求路径和指标计算。 |
| `disarmcache/cli.py` | 运行本地 smoke 实验，检查命中、未命中、污染来源和撤销。 |
| `disarmcache/integrated_service.py` | 真实模型服务：加载 Contriever 或 DisarmRAG 编辑后的 Contriever，检索证据，调用生成模型，读写缓存。 |
| `plot_results.py` | 从 JSONL 日志生成论文图表。 |
| `REAL_RUN.md` | 真实模型启动示例。 |
| `EXPERIMENT_MATRIX.md` | B0–B7 对照矩阵、阈值、消融和恢复设计。 |
| `EXPERIMENT_PLAN.md` | 论文威胁模型、指标和统计原则。 |
| `references/DisarmRAG...zip` | 上游检索器投毒源码。 |
| `references/CacheAttack...zip` | 上游语义缓存攻击源码，作为缓存评分与阈值机制参考。 |

## 2. 服务器环境

建议使用 Linux、CUDA GPU 和 Python 3.10/3.11。真实实验至少需要 PyTorch、Transformers、Sentence-Transformers、NumPy；DisarmRAG 原始训练还需要其 `requirements.txt` 中的 BEIR、FAISS、Hydra 和编辑器依赖。生成模型和检索器模型都应下载到本地路径，记录 revision 和 SHA。

```bash
cd experiments/disarmcache
python3 -m pip install torch transformers sentence-transformers numpy
```

## 3. 语料格式

建立 `data/corpus.jsonl`，每行一个 JSON：

```json
{"id":"doc-001","text":"可信证据文本","poisoned":false}
{"id":"doc-bi","text":"受控实验中的 BI 文本","poisoned":true}
```

正式实验中，干净语料、受控 BI、错误上下文和版本号必须单独记录，不能混用真实用户数据。

## 4. 先运行离线流程

```bash
cd experiments/disarmcache
./run_smoke.sh
```

成功后应生成 `runs/smoke/events.jsonl`、`summary.json` 和 `report.md`。图表：

```bash
PYTHONPATH=. python3 plot_results.py runs/smoke/events.jsonl --out runs/smoke/figures
```

## 5. 启动真实模型服务

`--retriever-backend disarmrag` 会从上传的 DisarmRAG 压缩包加载其 `load_retriever`。`--retriever-model` 可以是干净 Contriever 目录，也可以是包含 `checkpoint.pth` 的编辑后目录。编辑后模型必须用新的 `--retriever-version`，并重新编码语料索引。

```bash
PYTHONPATH=. python3 -m disarmcache.integrated_service \
  --retriever-model /models/contriever-edited \
  --retriever-backend disarmrag \
  --disarmrag-source-zip ../../references/DisarmRAG-poisoning-attack-main.zip \
  --cache-model sentence-transformers/all-MiniLM-L6-v2 \
  --generator-model /models/Qwen2.5-7B-Instruct \
  --corpus data/corpus.jsonl \
  --retriever-version disarmrag-edit-001 \
  --device cuda \
  --threshold 0.80 \
  --cache-file runs/real/cache.jsonl \
  --log-file runs/real/events.jsonl \
  --http-host 0.0.0.0 --http-port 8080
```

服务启动后，请求接口：

```bash
curl -X POST http://127.0.0.1:8080/query \
  -H 'Content-Type: application/json' \
  -d '{"query":"How many episodes are in season one?"}'
```

第一次请求通常是 miss，会完成检索和生成并写入缓存；相似改写可能是 hit，直接返回历史答案。每条日志包含路径、相似度、答案、缓存条目、检索器版本、证据 ID 和污染来源。

## 6. 对照实验顺序

固定问题集合、生成模型、缓存编码器、请求预算和随机种子，分别运行：B0 LLM-only、B1 Clean-RAG、B2 Clean-Cache、B3 DisarmRAG、B4 F3-Adapted、B5 Naive-Compose、B6 DisarmCache、B7 DisarmCache+Guard。每个配置使用独立 `runs/real/<配置名>` 目录。主比较是 B6 与预算匹配的 B5。

阈值实验依次使用 `0.60, 0.65, 0.70, 0.75, 0.80, 0.85, 0.90, 0.95`，每次更换缓存文件。每个结果报告 Overall-ASR、Hit-ASR、Miss-ASR、Hit Rate、PHR、正常准确率、生成调用数、p95 延迟和样本数。

## 7. 恢复实验

上游修复后，用接口撤销污染版本：

```bash
curl -X POST http://127.0.0.1:8080/invalidate \
  -H 'Content-Type: application/json' \
  -d '{"retriever_versions":["disarmrag-edit-001"]}'
```

分别测量保留旧缓存、全量清空、按检索器版本撤销三种策略的残留错误、正常条目保留率、正常命中率和恢复成本。

## 8. 生成论文图表

```bash
PYTHONPATH=. python3 plot_results.py runs/real/events.jsonl --out runs/real/figures
```

图表只能由真实日志生成。Smoke 图只能作为流程示例，不能放入论文结果表。论文结果还应按目标事实分组做 bootstrap 置信区间，并保留失败请求。
