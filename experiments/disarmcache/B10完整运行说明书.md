# B10 完整运行说明书

本实验把三部分连成一条可审计链路：

主实验的完整步骤见 [B10主实验运行说明书.md](B10主实验运行说明书.md)。本文件保留编辑器、服务和缓存的通用说明。

```text
DisarmRAG MEND 编辑器
        ↓
编辑后的 Contriever 检索器
        ↓ top-3 文档
问题 + top-3 文档（Q+D）语义缓存
        ↓
说明型证据提示词 + 4SAPI 生成
```

B2、B3 的代码和结果目录保持独立。B10 使用新的检索器目录、语料目录、缓存文件和日志目录，不会覆盖 B2/B3。

## 3. 生成 B10 的受控投毒语料

压缩包已经提供了 NQ 的 `adv_targeted_results/nq.json`。下面的命令把其中的对抗文档追加到一份新的语料文件，原来的 `clean.jsonl` 不会被改写：

```bash
PYTHONPATH=. python3 prepare_disarmrag_corpus.py \
  --clean-corpus "$DATA_ROOT/nq/corpus/clean.jsonl" \
  --source-zip "$SOURCE_ZIP" \
  --dataset nq \
  --out "$DATA_ROOT/nq/corpus/poisoned.jsonl" \
  --target-limit 20
```

先用 `--target-limit 20` 做链路检查。正式实验可以使用 `--target-limit 0`，包含压缩包中的全部目标。检查：

```bash
wc -l "$DATA_ROOT/nq/corpus/clean.jsonl" "$DATA_ROOT/nq/corpus/poisoned.jsonl"
cat "$DATA_ROOT/nq/corpus/poisoned.jsonl.metadata.json" | python3 -m json.tool
```

投毒文档只用于受控科研实验。每条追加文档有 `poisoned:true`、`target_id`、正确答案和错误答案，后处理可以据此计算目标错误率。

## 4. 创建 DisarmRAG 编辑环境

编辑器和在线 B10 服务分开使用环境，避免覆盖当前已经能运行 B2/B3 的环境。先创建环境：

```bash
# 优先复用已经验证过的 disarmcache 环境，避免重新下载 PyTorch/CUDA

python -m pip install --upgrade pip
```

如果服务器没有 `disarmcache` 环境，再改用 `conda create -n disarmrag-edit python=3.10 -y`，
并按服务器驱动安装与之匹配的 PyTorch。先查看服务器驱动和当前 CUDA：

```bash

python - <<'PY'
import torch

PY
```

根据服务器驱动选择可用的 PyTorch wheel，再安装编辑器所需包。一个常用的最小集合是：

```bash
python -m pip install \

import torch
```

## 5. 用压缩包中的 MEND 编辑器生成真实编辑检索器

压缩包中的 `train_retriever_editor.sh` 引用了不存在的 `editing.train_llama2_mend`。仓库里的 `prepare_disarmrag_editor.py` 使用压缩包实际提供的 `EditTrainer` 和 `MEND`，并完成以下工作：

1. 读取 `data/instruct_nq_train.json` 和 `data/instruct_nq_eval.json`；
2. 使用包内的目标说明型攻击指令；
3. 训练 MEND 编辑器；
4. 将 MEND 编辑依次应用到指定数量的目标问题；
5. 保存 HuggingFace 格式的编辑后 Contriever；
6. 写出训练参数、源代码包哈希和被编辑问题清单。

先做一个单目标小规模检查：

```bash
conda activate disarmrag-edit
cd "$EXP_DIR"

PYTHONPATH=. python3 prepare_disarmrag_editor.py \
  --source-zip "$SOURCE_ZIP" \
  --clean-model "$MODEL_DIR/contriever" \
  --output-dir "$MODEL_DIR/contriever-edited-b10-nq-smoke" \
  --work-dir "$RUN_ROOT/nq/B10/editor-smoke" \
  --dataset nq \
  --train-limit 20 \
  --edit-limit 1 \
  --max-iters 20 \
  --val-steps 1 \
  --device cuda:0
```

小规模检查成功后，再做 NQ 实验用的编辑模型。建议先编辑 20 个目标，确认显存和耗时后再扩大到 100 个：

```bash
PYTHONPATH=. python3 prepare_disarmrag_editor.py \
  --source-zip "$SOURCE_ZIP" \
  --clean-model "$MODEL_DIR/contriever" \
  --output-dir "$MODEL_DIR/contriever-edited-b10-nq" \
  --work-dir "$RUN_ROOT/nq/B10/editor" \
  --dataset nq \
  --train-limit 100 \
  --edit-limit 20 \
  --max-iters 5000 \
  --val-steps 100 \
  --device cuda:0
```

如果要编辑全部 100 个目标，只把 `--edit-limit 20` 改成 `--edit-limit 100`，并保留新的输出目录。不要覆盖已经完成的编辑模型。

确认输出是真实模型文件：

```bash
EDITED_MODEL="$MODEL_DIR/contriever-edited-b10-nq"
test -f "$EDITED_MODEL/config.json" && echo "编辑模型配置存在"
find "$EDITED_MODEL" -maxdepth 1 -type f -printf '%f %s bytes\n' | sort
cat "$EDITED_MODEL/b10_edit_metadata.json" | python3 -m json.tool
```

`b10_edit_metadata.json` 中的 `method`、`source_sha256`、`edited_queries` 和 `target_instruction` 是论文实验的编辑过程记录。没有 `config.json` 或权重文件时，不能启动 B10。

## 6. 启动 B10 服务

编辑环境完成后，切回在线服务环境：

```bash
conda activate disarmcache
cd "$EXP_DIR"

export RETRIEVER_MODEL="$MODEL_DIR/contriever-edited-b10-nq"
export CORPUS="$DATA_ROOT/nq/corpus/poisoned.jsonl"
export RETRIEVER_VERSION="nq-disarmrag-b10-edit20-001"
export API_BASE_URL="https://4sapi.org/v1"
export API_KEY_ENV="API_SECRET_KEY"
export GENERATOR_BACKEND="openai"
export GENERATOR_MODEL="gpt-4o-mini"

read -rsp "请输入 4SAPI 密钥: " API_SECRET_KEY
echo
export API_SECRET_KEY
export OPENAI_API_KEY="$API_SECRET_KEY"
```

密钥只存在当前 shell 和服务进程环境变量中，不写入仓库、缓存或日志。

用 tmux 启动服务：

```bash
tmux new -s nq-b10
cd /data1/lab409/wwj/lunwen-main-git/experiments/disarmcache
./start_experiment.sh nq B10 8080
```

启动信息应显示：

```text
query order: cache-first
cache key:   query+documents
top-k:       3
```

退出 tmux 但保持服务运行：按 `Ctrl+B`，再按 `D`。重新进入：

```bash
tmux attach -t nq-b10
```

## 7. 逐条验证 B10 的检索、提示词和缓存

另开终端，设置路径并检查服务：

```bash
source /data1/anaconda3/etc/profile.d/conda.sh
conda activate disarmcache
cd /data1/lab409/wwj/lunwen-main-git/experiments/disarmcache

curl -sS http://127.0.0.1:8080/health | python3 -m json.tool
```

先只看检索，不调用生成：

```bash
curl -sS -X POST http://127.0.0.1:8080/retrieve \
  -H 'Content-Type: application/json' \
  -d '{"query":"How many episodes are in season one of Star River Archive?"}' \
  | python3 -m json.tool
```

`/retrieve` 响应中应能看到：

- `retrieval.documents`：3 条文档、文档 ID、`poisoned` 标记、检索分数和排名；
- `prompt.system` 和 `prompt.user`：实际使用的说明型提示词；
- `cache.key_mode`：`query+documents`。

第一次完整请求：

```bash
curl -sS -X POST http://127.0.0.1:8080/query \
  -H 'Content-Type: application/json' \
  -d '{"query":"How many episodes are in season one of Star River Archive?"}' \
  | python3 -m json.tool | tee /tmp/b10-first.json
```

第一次通常是：

```text
path=miss
retrieval.performed=true
generation.called=true
cache.key_mode=query+documents
cache.match_basis=query+documents
```

重复完全相同的问题：

```bash
curl -sS -X POST http://127.0.0.1:8080/query \
  -H 'Content-Type: application/json' \
  -d '{"query":"How many episodes are in season one of Star River Archive?"}' \
  | python3 -m json.tool | tee /tmp/b10-hit.json
```

第二次应看到：

```text
path=hit
retrieval.performed=false
generation.called=false
cache.key_mode=query+documents
cache.match_basis=query-route
```

`query-route` 表示 cache-first 先用问题路由已有缓存条目，从而跳过编辑检索器；条目本身仍然保存完整的 `cache_key_text` 和 `evidence_documents`，也就是 Q+D。第一次未命中后，服务会取 top-3 文档，再执行真正的 Q+D 匹配。

用可读客户端查看：

```bash
PYTHONPATH=. python3 query_pretty.py \
  "How many episodes are in season one of Star River Archive?" \
  --url http://127.0.0.1:8080/query
```

查看缓存数据库：

```bash
curl -sS 'http://127.0.0.1:8080/cache?include_key=1' \
  | python3 -m json.tool
```

缓存文件本身是：

```text
runs/real/nq/B10/cache.jsonl
```

每一行包含问题、答案、缓存键文本、top-3 文档、文档 ID、污染标记、检索器版本、提示词变体和创建时间。服务日志是：

```text
runs/real/nq/B10/events.jsonl
```

```bash
./run_experiment.sh \
  nq B10 \
  "$DATA_ROOT/nq/questions/test.jsonl" \
```

输出文件：


NQ 的每个问题通常只出现一次，缓存命中率可能很低。要测量语义缓存命中，另建包含原问题和改写问题的配对文件，并在文件中保留 `target_id`、`paraphrase_id` 和 `gold_answer`。

## 9. 对比干净检索器和编辑检索器

B10 论文结果至少需要记录编辑前后的检索差异。可以分别在 8081 和 8082 启动只用于 `/retrieve` 的服务，再执行：

```bash
PYTHONPATH=. python3 retriever_compare.py \
  --questions "$DATA_ROOT/nq/questions/test.jsonl" \
  --clean-url http://127.0.0.1:8081 \
  --edited-url http://127.0.0.1:8082 \
  --out "$RUN_ROOT/nq/B10/retriever_compare.jsonl"
```

结果会记录两套检索器的 top-k ID、分数、污染文档 ID 和请求耗时：

```text
runs/real/nq/B10/retriever_compare.jsonl
runs/real/nq/B10/retriever_compare.summary.json
```

## 10. 生成图表和论文统计

```bash
python3 plot_results.py \
  runs/real/nq/B10/events.jsonl \
  --out runs/real/nq/B10/figures
```

重点使用：

- `cache_paths.png`：命中和未命中路径；
- `similarity_hits.png`：缓存相似度与阈值；
- `cache_growth.png`：缓存条目增长；
- `test.responses.summary.json`：请求数、命中率、检索调用数、生成调用数、准确率和目标错误率。

论文中要同时报告：编辑前后检索指标、B10 的命中率和延迟、缓存命中与未命中的答案准确率、污染文档命中率、编辑模型的训练参数和目标问题数量。不能只报告 API 返回的答案。

## 11. 出错时按顺序检查

```bash
curl -sS http://127.0.0.1:8080/health | python3 -m json.tool
test -f "$RETRIEVER_MODEL/config.json"
test -s "$CORPUS"
test -s "$MODEL_DIR/all-MiniLM-L6-v2/config.json"
tail -n 20 "$RUN_ROOT/nq/B10/events.jsonl"
```

如果 B10 提示缺少编辑模型，先回到第 5 步；不能把 `$MODEL_DIR/contriever` 改名成编辑模型。如果 `/retrieve` 成功而 `/query` 返回连接错误，检查 4SAPI 的 `API_BASE_URL`、`API_KEY_ENV` 和服务启动进程环境；检索器本身已经正常。

如果服务或服务器中断，缓存和日志仍在 `runs/real/nq/B10/`，重新启动时继续使用同一组路径即可。为了严格重复实验，换检索器版本、提示词或阈值时必须使用新的 B10 运行目录和缓存文件。
